## 핵심 결과

기존 **XBTUSD 총손익 차이 0.02745234 BTC의 발생 요인을 설명했습니다.** 두 자료의 비교 종료 시점과 동시 체결 묶음의 원가 배분 방식이 원인이었습니다. 개선한 복원값은 제공된 XBTUSD 지갑 총손익과 정확히 일치합니다. 다만 일별 기장에서는 12일에 각각 1~2사토시 차이가 남으며, 전체 기간 순차이는 0입니다.

**지갑 잔액 불일치 154일 중 152일**은 원본의 표시 정밀도와 정확히 부합합니다. 남은 2일은 하나의 출금에 적힌 날짜와 잔액 반영 순서가 충돌합니다. 별도 시나리오로 계산 순서를 바꾸면 산술 관계가 맞지만 실제 처리일은 확정하지 않았습니다. 원본 행을 수정하거나 삭제하지 않았습니다.

| 기존 문제 | 확인한 설명 | 남은 불확실성 |
| --- | --- | --- |
| 작은 잔액 차이 152일 | 재구성 잔액을 원본 자릿수로 반올림하면 정확히 일치 | 표시값만으로 숨겨진 자릿수를 복원할 수는 없음 |
| 2018.04.27~28 잔액 차이 | 27일자로 적힌 출금 잔액이 28일 손익을 반영 | 요청일·처리일·내보내기 날짜 중 무엇인지 미확정 |
| XBTUSD 총차이 2,745,234사토시 | 정산 범위 차이 1,958,048 + 최종 원가 배분 차이 787,186 | 일별 12일에 최대 2사토시 차이 |

계좌 전체 순실현손익 **3,537.32369404 BTC**, XBTUSD 원장 손익 **2,007.08464645 BTC**, 입출금과 마지막 지갑 잔액은 바뀌지 않습니다. 원장 총액을 고친 것이 아니라 비교 오차의 설명을 구체화했습니다.

## 1. 표시 정밀도로 설명되는 152일

완료 거래의 잔액 스냅샷이 있는 날짜는 1,380일입니다. 이 중 1,226일은 정수 사토시 기준으로 그대로 맞습니다. 나머지 152일은 재구성 값을 원본의 지수표기 정밀도로 반올림하면 일치합니다.

2021년 6월 5일의 예입니다.

```text
재구성 잔액: 100,334,421,760 사토시
원본 문자열: 1.00334E+11
표시값:      100,334,000,000 사토시
단순 차이:        -421,760 사토시 = -0.00421760 BTC
```

해당 문자열의 표시 단위는 **1,000,000사토시, 즉 0.01 BTC**입니다. 재구성 잔액을 이 단위로 반올림하면 원본과 정확히 같습니다. 각 문자열의 Decimal 지수에서 표시 단위를 읽었으며, 차이가 작다는 이유로 임의 허용오차를 적용하지 않았습니다.

152일 전체가 같은 검사를 통과합니다. 따라서 현금 누락의 증거가 아니라 **표시 정밀도와 부합하는 차이**로 분류할 수 있습니다. 이것이 계정 자체의 외부 인증을 뜻하지는 않습니다.

근거: [전체 일별 분류](../results/accounting_audit/wallet_daily_classification.csv), [기존 불일치 154일 목록](../results/accounting_audit/wallet_154_residual_days.csv). 원본 행 번호는 헤더를 포함한 1부터 시작하는 CSV 행 번호입니다.

## 3. XBTUSD 정산 범위 맞추기

BitMEX의 공식 설명은 일별 지갑 손익을 전날 12:00 UTC부터 해당일 12:00 UTC까지의 구간으로 설명합니다. 제공 자료는 **시작을 포함하고 끝은 제외하는** `[전날 12:00, 해당일 12:00)` 처리와 강하게 부합합니다. [공식 손익 설명](https://support.bitmex.com/hc/en-gb/articles/6205277211037-How-do-I-manually-calculate-my-Realised-PNL).

같은 복원 이벤트로 정산 시각 6개와 날짜 이동 3개 조합을 비교했습니다. 정오 경계와 다음 날 표기 조합의 오차가 현저히 작았습니다. 날짜마다 별도 이동을 맞춘 것은 아닙니다. [비교 표](../results/accounting_audit/settlement_window_comparison.csv).

마지막 체결 파일에는 지갑 마지막 정산 구간 이후의 펀딩이 있습니다.

| 논리 체결시각 UTC | 펀딩 execcomm, 사토시 | 계좌 순효과 | 배정되는 기장 날짜 |
| --- | ---: | ---: | --- |
| 2021-12-31 12:00:00 | −2,848,748 | +2,848,748 | 2022-01-01 |
| 2021-12-31 20:00:00 | +890,700 | −890,700 | 2022-01-01 |
| 합계 | | **+1,958,048** | 제공된 지갑 범위 밖 |

이 두 행이 기존 차이 중 **0.01958048 BTC**를 설명합니다. 행을 삭제하거나 오류로 취급하지 않고 범위 밖 이벤트로 보존했습니다. 2022년 1월 지갑은 제공되지 않았으므로 실제로 기장된 해당일 손익을 확인했다고 주장하지 않습니다. [종료 경계 기록](../results/accounting_audit/xbtusd_after_wallet_cutoff.csv).

## 4. 동시 체결과 마지막 포지션 반전

남은 **0.00787186 BTC**는 실현손익과 미결제 포지션 원가 사이의 배분 차이입니다. **2021-12-24 03:28:15.683307**에 주문 `7623ce3f-8206-4be4-8ad0-b3a312832fb8`의 **매도 76체결**이 발생했습니다. 합계는 **2,855,500계약**, 가격은 51,100~51,025 USD의 55개 수준이며, 직전 포지션은 **919,900계약 롱**이었습니다.

기존 모델은 누적 체결수량 순으로 앞선 체결부터 롱을 종료합니다. 개선 모델은 **정확히 같은 시각 + 주문 ID + 방향**의 체결을 먼저 합친 뒤 기록된 원가를 종료 수량과 신규 수량에 비례 배분합니다. 수 분에 걸친 전체 주문을 한 번에 묶거나 임의의 초 단위 간격으로 합치는 방식은 아닙니다. 주문 UUID가 0인 청산 체결은 개별 식별을 유지합니다.

```text
묶음의 기록된 체결 원가:            5,592,397,211 사토시
개별 체결 순서에 따른 종료 원가:    1,800,804,897 사토시
묶음 평균에 따른 종료 원가:
  5,592,397,211 × 919,900 / 2,855,500
  = 1,801,592,083.487620...
사토시 반올림 후 종료 원가:          1,801,592,083 사토시
차이:                                    787,186 사토시
```

이 처리는 787,186사토시를 실현손익과 남은 포지션 원가 사이에서 다르게 배분합니다. 최종 포지션 수량 **−29,080,100계약**은 같습니다. 기존 모델의 마지막 절대 원가는 **56,922,926,304사토시**, 개선 모델은 **56,922,139,118사토시**입니다.

같은 규칙을 XBTUSD **941,007체결 전체**에 적용하면 **506,211개 회계 묶음**이 됩니다. 마지막 차이만 맞추는 일회성 보정값을 넣지 않았습니다. 이 묶음은 회계 계산 단위이며 새로 추정한 매매 의사결정 횟수가 아닙니다.

전체 기간의 일치는 이 배분 방식에 대한 강한 관측 근거입니다. 거래소 비공개 구현이나 모든 동일 시각 묶음이 실제 매칭엔진의 한 트랜잭션이라는 사실까지 확인한 것은 아닙니다. [76개 원본 체결](../results/accounting_audit/xbtusd_final_reversal_source_fills.csv), [복원한 묶음](../results/accounting_audit/xbtusd_final_reversal_batch.csv).

## 5. 정수 사토시 처리와 남은 12일

개선 모델은 원가와 실현손익을 정수 사토시로 관리하며, 비례 배분액을 반올림하고 남은 원가는 잔여 포지션에 보존합니다. 체결가격으로 원가를 다시 추측하지 않습니다. BitMEX는 2021년 6월 XBTUSD 최소 단위를 1계약에서 100계약으로 바꾸면서 사토시 환산 정밀도와 기존 포지션 처리도 변경했습니다. 기록된 체결 원가를 사용하면 전체 기간에 하나의 가격 반올림 규칙을 소급 적용하는 문제를 피할 수 있습니다. [당시 기술 공지](https://www.bitmex.com/blog/the-technical-details-of-our-lot-size-change-on-xbtusd-swap-and-xbt-futures).

| 같은 지갑 기간으로 맞춘 모델 | 총차이 | 일별 최대 절댓값 | 일별 차이 절댓값 합계 |
| --- | ---: | ---: | ---: |
| 개별 체결·부동소수 비례 원가 | 약 +787,186사토시 | 약 4,196,756사토시 | 약 15,556,205사토시 |
| 동시 체결 묶음·부동소수 원가 | 약 −0.49사토시 | 약 66.94사토시 | 약 1,723.19사토시 |
| 묶음·정수 최근접 반올림 | **0사토시** | **2사토시** | **14사토시** |
| 묶음·내림 | 0사토시 | 492사토시 | 22,788사토시 |

내림 모델도 총액만 보면 맞으므로 총액 일치만으로 방법을 검증할 수는 없습니다. 최근접 반올림의 half-even과 half-up은 이번 비교에서 일별 결과가 같아, 정확히 절반인 경우의 처리 규칙은 **식별되지 않았습니다.**

실제 XBTUSD 기장일 1,377일 중 **1,365일이 정확히 일치**합니다. 남은 12일은 작은 차이가 발생했다가 상쇄되는 6개 구간으로 나타납니다. 각 차이는 1~2사토시, 절댓값 합계는 14사토시, 전체 순차이는 0입니다. [지갑 ID·원본 행 번호를 포함한 목록](../results/accounting_audit/xbtusd_small_residual_days.csv), [관련 체결 파일과 행 범위](../results/accounting_audit/xbtusd_small_residual_source_ranges.csv).

달력 전체 1,398일로 보면 1,386일이 정확히 맞습니다. 추가 21일에는 XBTUSD 손익 원장 행이 없고 모델도 0입니다. 원장 행 부재는 별도 표시하며 실제 0원 기장 행이 있었다고 표현하지 않습니다.

12일의 작은 차이는 거래소 내부 처리 수준에서 아직 설명하지 못했습니다. 반올림 순서나 세부 묶음 처리가 후보일 수 있으나 확인된 원인은 아닙니다. 허용오차로 없애거나 원장에 맞춰 재배분하지 않았습니다.

## 6. 총차이의 정확한 분해

```text
기존 차이를 사토시로 반올림: 2,745,234사토시 = 0.02745234 BTC
지갑 범위 밖 펀딩 차감:      1,958,048사토시 = 0.01958048 BTC
최종 원가 배분 차이 차감:      787,186사토시 = 0.00787186 BTC
개선 모델의 총잔여 차이:             0사토시
```

기존 부동소수 계산에는 사토시보다 작은 수치 오차가 있었습니다. 위 분해는 체결 원가·수수료·펀딩·최종 잔여 원가로부터 계산했으며 설명 없는 조정값을 사용하지 않습니다.

개선 모델로 **체결 파일 전체**를 계산하면 순손익은 **2,007.10422693 BTC**입니다. 마지막 지갑 정산 구간까지만 비교하면 **2,007.08464645 BTC**로 원장과 정확히 같습니다. 누적 부호 있는 체결 원가와 최종 포지션 원가를 이용해 보존식도 별도로 검산했습니다.

## 7. 재현 방법과 코드 변경

```text
python scripts/analyze.py
python scripts/accounting_audit.py
python -m unittest discover -s tests -v
python scripts/verify.py
```

원본 계정 파일을 사용해 오프라인 재현할 수 있습니다. 기준 manifest와 SHA-256을 비교하며 결과는 `results/accounting_audit/`에 분리했습니다. 기존 개별 체결 방식의 포지션 구간 통계는 비교용으로 남깁니다. 이번 작업에서 승률·보유기간을 동시 체결 묶음 방식으로 조용히 교체하지 않았습니다.

추가로 CSV 저장 코드의 `%.10g` 문제를 수정했습니다. 결측값 때문에 부동소수 열로 표현된 큰 잔액을 유효숫자 10자리로 저장하면 사토시 일부가 잘릴 수 있었습니다. 이제 값을 다시 읽어도 보존되는 기본 직렬화를 사용합니다. 이것이 기존 메모리 계산의 154일 차이나 총손익 차이 원인은 아니며, 별도의 출력 정밀도 문제입니다. 73,726,973,405사토시와 결측값이 함께 있는 경우를 회귀 테스트에 포함했습니다.

테스트는 정산 경계, 부분 종료·반전의 원가 보존, 묶음과 개별 체결 배분 차이, 큰 정수 반올림, 수수료 중복 방지, CSV 정밀도를 다룹니다. 전체 자료를 검토한 회계 복원 연구이지 미사용 데이터에 대한 예측 검증은 아닙니다.
