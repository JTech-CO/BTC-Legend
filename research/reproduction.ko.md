# 재현 절차와 로컬 연구 패키지

v0.7 · 기본 언어 [English](reproduction.en.md) · [통합 백서](../reports/whitepaper.ko.md) · [데이터 사전](data-dictionary.ko.md)

## 재현할 수 있는 범위

보고서·연구 코드·파생 표·도표·브라우저 앱을 로컬 검토 패키지로 구성했습니다. 수치를 정확히 다시 계산하려면 원본 계좌 파일 5개와 저장된 시장 입력이 추가로 필요합니다. 검토 ZIP에는 이 입력과 개인용 SQLite 색인을 넣지 않습니다. 원본 없이 문서를 읽을 수 있다는 것과 원본 없이 모든 수치를 재계산할 수 있다는 것은 다릅니다.

계좌 귀속·진위·외부 계좌를 포함한 전체성은 미인증이며 해시는 파일 동일성만 확인합니다. 소프트웨어 라이선스나 원본·파생 데이터의 재배포 권한은 임의로 정하지 않았습니다. 소유자 검토용 로컬 파일을 준비하며, 게시·저장소 초기화·커밋·푸시는 수행하지 않습니다. 검토 묶음에도 상세 파생 계좌 관측이 있으므로 익명화 자료가 아닙니다.

## 실행 환경

Python 3.11 이상과 [requirements.txt](../requirements.txt)의 지원 범위를 사용합니다. 사용자가 관리하는 가상환경에서 설치할 수 있습니다.

```text
python -m pip install -r requirements.txt
```

탐색기 서버는 Python 표준 라이브러리만 사용하며 색인 생성에는 pandas가 필요합니다. 브라우저는 로컬 HTML·CSS·JavaScript를 사용하며 CDN·프런트엔드 패키지 설치·계좌 연결·인터넷 요청은 없습니다. 차트도 로컬에서 만듭니다.

[runtime.json](runtime.json)은 패키지 목록 생성 환경을 기록하며 모든 환경을 고정한 의존성 잠금 파일은 아닙니다. 개발 시 과학 도표에는 Python 3.14.0, NumPy 2.3.4, pandas 2.3.3, matplotlib 3.10.7을 사용했고, 자료 분석·검증은 실행기가 기록한 번들 Python 환경에서도 수행했습니다. 플랫폼별 부동소수점 차이는 명시한 허용 오차로 검사하고 정수 현금·수량 항등식은 정확히 대조합니다.

## 입력을 복원한 뒤 검증

[input-lock.json](input-lock.json)의 상대 경로에 원본 계좌·기준가격·제공자 표본·명세·수집 기록을 같은 바이트로 복원합니다. 서한은 수치 입력에 포함하지 않습니다. 계좌 원본 이름과 해시는 [원본 목록](../results/manifest.json)에도 있습니다.

```text
python scripts/reproduce.py --mode preflight
python scripts/reproduce.py --mode verify
```

사전 검사는 누락·해시 불일치를 표시하고 분석 전에 중단하며 입력을 내려받거나 덮어쓰지 않습니다. 검증 모드는 전체 단위 테스트와 v0.1-v0.6 검증 스크립트 5개를 순서대로 실행하고 첫 실패에서 중단합니다. 명령·종료 코드·로그는 `results/release/`에 기록합니다. `reproduction.json`은 기존 결과 검증과 전체 재계산을 구분합니다. 검증 통과를 전체 파이프라인을 새로 재현한 것으로 표시하지 않습니다.

## 저장된 스냅샷에서 전체 재계산

```text
python scripts/reproduce.py --mode rebuild --explorer
```

명시적인 재계산 모드는 연구 결과·도표를 다시 만들고 탐색기 색인을 생성한 다음 테스트·검증을 실행합니다. 같은 Python 환경에 NumPy·pandas·matplotlib가 필요합니다. 네트워크를 사용하지 않으며 원본이 아닌 파생 결과를 교체합니다. Windows에서는 실행 중인 탐색기를 종료한 뒤 SQLite를 교체하세요. 계좌 CSV·복원 사건·약 0.88 GB의 로컬 색인 때문에 수 GB의 작업 공간과 수 분 이상의 시간이 필요합니다.

의존 순서는 다음과 같습니다.

1. `analyze.py`, `accounting_audit.py`: 기초 분석과 원본 해시·개선 회계.
2. `market_analysis.py`: 저장된 과거·현재 시장 비교. 후속 사건·행동 연구의 입력입니다.
3. `event_study.py`, `portfolio_risk.py`: 기장 사건·계약 명세·보유 수량·기준가격 위험.
4. `research_events.py`: 원주문·계약별 사건·보유 에피소드.
5. `mark_sample_analysis.py`, `intraday_behavior.py`, `flow_adjusted_returns.py`: 월초 마크·장중 수량·조건부 수익률.
6. `research_priorities.py`, `research_sensitivity.py`: 조정 행동·성과 기여·손실 후 반응·가정 민감도.
7. 도표 스크립트 5개와 선택한 탐색기 색인 생성, 이후 테스트·검증.

다운로드 도구는 별도 선택 단계입니다. `fetch_market.py`는 원래 고정된 기준일의 시장 데이터를, `fetch_portfolio_market.py`는 기준가격·명세를, `fetch_historical_marks.py`는 `research_events.py` 이후 선택된 제공자 표본을 요청합니다. 공급자의 접근 가능성·과거 수정 때문에 같은 바이트를 재확보하지 못할 수 있습니다. 새 다운로드는 자동으로 원본과 같은 입력이 되지 않습니다. 불일치를 숨기기 위해 `lock-inputs`를 실행하지 마세요. 의도적인 입력 변경은 검토 후 새로운 연구 스냅샷으로 버전 관리해야 합니다.

## 탐색기 실행

v0.5-v0.6 선행 결과가 있는 상태에서 실행합니다.

```text
python scripts/build_explorer.py
python scripts/verify_explorer.py
python scripts/serve_explorer.py
```

[로컬 탐색기](http://127.0.0.1:8765)를 엽니다. 포트가 사용 중이면 `--port 8766`을 지정하고 종료는 Ctrl+C입니다. 서버는 127.0.0.1에만 연결하고 SQLite를 읽기 전용으로 열며, 쓰기 API·외부 출처 요청·임의 파일 경로·일반 파일 탐색을 제공하지 않습니다. 개인 연구 도구이며 인터넷 배포용 서버가 아닙니다.

날짜·계약을 선택하여 시작·종료 보유량, 원주문, 수량 사건, 지갑 기장, 펀딩, 월초 마크, BOD/MID/EOD 수익률 시나리오를 확인합니다. 요청 기간의 첫 4일에는 시장 가격만 있고 계좌 관측은 없으므로 자산 0으로 표시하지 않습니다. 원본 버튼은 **해당 원주문 전체 체결**, 또는 0 ID 사건의 고유 체결 1개를 보여줍니다. 따라서 시각별 묶음의 원본 연결에는 그 묶음보다 많은 체결이 나올 수 있습니다. 페이지당 100개입니다. 가격은 계약의 호가 통화를 유지하며 계약 수량을 BTC 수량으로 바꾸어 표시하지 않습니다.

계약 필터는 포지션·주문·펀딩·사건 행에 적용됩니다. 계좌 카드·지갑·자본 차트·수익률은 전체 계좌를 유지합니다. 월초 가격 상세 표는 날짜·필터 조건에서 최근 최대 200개 관측만 보여주며 전체 파일은 로컬 색인에 있습니다. 일별 자본 차트는 결측을 끊고 입출금을 포함하므로 투자 수익률 차트가 아닙니다.

첫 화면은 영어이며 선택한 언어는 브라우저의 로컬 저장소에 유지됩니다. 날짜·계약은 로컬 URL에도 반영합니다. JSON 내보내기는 선택한 날짜·입력 해시와 현재 표시된 사건·원본 페이지를 전체 건수와 함께 담습니다. 전체 체결 내보내기가 아닌 사례 스냅샷이며 계좌 상세가 포함된 사용자의 로컬 파일입니다.

## 검토 묶음 생성·검증

코드·문서를 의도적으로 수정했다면 목록을 갱신한 뒤 ZIP을 생성합니다.

```text
python scripts/research_release.py catalog
python scripts/research_release.py package
```

`catalog`는 CSV 헤더 사전과 검토 패키지 파일의 해시를 만듭니다. `package`는 목록 작성 후 파일이 바뀌었으면 중단합니다. ZIP 항목의 시각을 고정하고 내부 파일의 해시·CRC를 대조하여 `dist/btc-legend-v0.7-review.zip`을 만듭니다. 묶음 해시·크기·검증 상태는 `results/release/package.json`에 있습니다. 네트워크·Git 명령은 실행하지 않습니다. 수정 후 목록을 재생성해야 하며 목록 자체의 자기 해시는 포함하지 않습니다.

포함: README·코드·테스트·탐색기 화면·EN/KR 문서·파생 표·도표·출처·입력 해시. 제외: `data/` 전체, `.git/`, SQLite, 재생성 가능한 대형 원주문·사건 캐시, 실행 로그, 이전 압축파일. 일부 상세 파생 표에는 원본 참조와 거래 식별자가 남아 있습니다. 원본 제외가 파생물의 재배포 권한을 부여하지는 않습니다. [스키마 목록](schema-inventory.json)은 각 결과의 헤더·해시·크기·포함 여부를, [배포 목록](release-manifest.json)은 실제 묶음 파일을 기록합니다. 제외 입력으로 향하는 문서 링크는 원래 작업 공간을 복원해야 열리며 ZIP만으로는 유효하지 않을 수 있습니다.

## 검증 범위

탐색기의 [자료·API 정합성 검사 34개](../results/explorer/validation.json)를 통과했습니다. 전체 단위 테스트는 44개이며 읽기 전용 SQLite, HTTP 제한, 쿼리 인자, 사전 검사 불일치, 패키지 제외 규칙을 포함합니다. 브라우저에서는 EN/KR·계약 필터·원본 연결·페이지 이동·평가 결측·계좌 관측 부재·마크 표본일을 확인합니다. 기존 검증도 보존하며 검사 수를 외부 인증으로 해석하지 않습니다. 연구 한계는 통합 백서에 유지합니다.
